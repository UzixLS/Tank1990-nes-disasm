# Работа с производными версиями

Обычная цель `make all` не читает оригинальный ROM и подходит для сборки
производной версии. `make verify` предназначена только для проверки исходного
восстановления: после намеренного изменения игры она, как и ожидается, сообщит
о первом отличающемся байте.

Локальные пути к ca65/ld65 и Unix-инструментам задаются в игнорируемом
`Makefile.local`; пример находится в `Makefile.local.example`.

## Что редактировать

- карты Tank 1990: `assets/levels/tank/*.map`;
- пять дополнительных карт: `assets/levels/extra/*.map`;
- классические карты: `assets/levels/classic/*.map`;
- тайлы спрайтов: `assets/chr/sprites.bmp`;
- фоновые тайлы: `assets/chr/background.bmp`;
- палитры: `assets/palettes/*.pal`;
- фоновые метатайлы 2×2: `assets/metatiles/background.tsa`;
- игровой код и таблицы: `src/*.s` и `src/*.inc`.

Основные таблицы диспетчеризации в `src/prg1_lo.s` используют символические
ссылки: `TankLogicHandlers`, `TankDrawHandlers`, `ProjectileLogicHandlers`,
`ProjectileDrawHandlers`, `PowerUpEffectHandlers` и `AudioCommandHandlers`.
У аудиопотоков есть точки входа `AudioSequence00`–`AudioSequence27`; несколько
потоков могут совместно использовать один и тот же хвост данных. Формат
потоков и команды интерпретатора описаны в `docs/audio.md`.

BMP используют только индексы палитры 0–3. Цвета BMP нужны для удобного
просмотра; в NES окончательный цвет задаётся палитрами из PRG.

## Ограничения текущей раскладки

Конфигурация `cfg/tank1990.cfg` фиксирует адреса областей оригинального NROM.
Изменение байтов внутри области допустимо, но её переполнение остановит
линковку. Это специально защищает таблицы уровней, векторы и код от незаметного
сдвига. Для расширения ROM нужно завести отдельную конфигурацию линкера и
изменить iNES-заголовок/mapper осознанно.

Имена `Lxxxx` всё ещё означают исследованные только до уровня границ
инструкций адреса. Они не считаются стабильным API. Смысловые имена из
`ram.inc` и имена процедур без адресного префикса предпочтительны для нового
кода.
