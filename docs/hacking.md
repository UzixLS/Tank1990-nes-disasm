# Редактирование и ромхаки

`make all` собирает ROM, `make test-tools` проверяет конвертеры без исходного
образа. Цели `verify`, `test-assets`, `test` и `audit` сравнивают результат
с оригинальным `Tank 1990 (Ch).nes` и после изменения игры могут завершаться
ошибкой. Локальные пути к инструментам задаются в `Makefile.local` по образцу
`Makefile.local.example`.

## Ассеты

Форматы и пути перечислены в [README](../README.md#ассеты). Файлы в `build/`
пересоздаются; правки нужно вносить в `assets/` и `src/`.

Makefile собирает 105/36/1 карт из `extra`/`classic`/`unused`. Замена
содержимого `.map` сохраняет размер раскладки. Добавление записей требует
изменить Makefile, дескрипторы загрузчика и конфигурацию линкера.

`LoadAndDrawStage` выбирает карты из `ClassicLevels` по формуле
`base + ((2 * wraps) mod 6) + 91 * (normalizedStage - 1)`. При повторном
обходе каталога поток сдвигается на 2/4 байта. Последнее окно может захватить
`$FCFC-$FCFF` — начало кода `src/frontend_extensions.s`. Для подключения
карт `extra` нужны дескриптор и допустимый диапазон `StageNumber`.

BMP используют индексы 0–3; окончательные цвета в игре задают палитры PRG.

## Код и таблицы

Расположение подсистем приведено в [карте ROM](memory-map.md).
Общие адреса RAM находятся в `src/ram.inc`, маски, состояния и размеры
пулов — в `src/game.inc`. Временные байты с разным назначением на разных
экранах именуются локально в модулях.

| Таблица обработчиков | Файл |
|---|---|
| `TankLogicHandlers`, `TankDrawHandlers` | `src/tank_tables.s` |
| `ProjectileLogicHandlers`, `ProjectileDrawHandlers` | `src/projectiles.s` |
| `PowerUpEffectHandlers` | `src/powerup_pickup.s` |
| `AudioCommandHandlers` | `src/audio_engine.s` |

Периоды, указатели и аудиобайткод находятся в `src/audio_data.s`.
Потоки `AudioSequence00`–`AudioSequence27` могут использовать общие хвосты.
Состояния `AudioStreamStates`: 0 — выключен, 1 — запрос запуска,
2 — работает. Формат команд описан в [аудиобайткоде](audio.md).

## Раскладка ROM

`cfg/tank1990.cfg` фиксирует адреса областей NROM. Переполнение области
останавливает линковку. Расширение ROM требует другой конфигурации линкера
и изменения iNES-заголовка/mapper.

Порядок `.include` задаёт физическое расположение кода. Его изменение
затрагивает абсолютные адреса, таблицы обработчиков и переходы между
продолжениями процедур. Метки `Lxxxx` служат адресными якорями; новый код
должен обращаться к смысловым именам.

`InitializeRuntimeChecksumGuard` вычисляет XOR трёх участков ROM.
При изменении этих участков нужно обновить ожидаемую сумму или изменить
проверку: начиная с этапа `$1A`, несовпадение может вызвать косвенный переход
через `ScratchPtr`. Участки и условия описаны в `src/runtime_checksum_init.s`
и `src/runtime_integrity.s`.
