# Работа с производными версиями

Обычная цель `make all` не читает оригинальный ROM и подходит для сборки
производной версии. `make verify` предназначена только для проверки исходного
восстановления: после намеренного изменения игры она, как и ожидается, сообщит
о первом отличающемся байте.

Локальные пути к ca65/ld65 и Unix-инструментам задаются в игнорируемом
`Makefile.local`; пример находится в `Makefile.local.example`.

## Что редактировать

- карты Tank 1990: `assets/levels/tank/*.map`;
- пять дополнительных карт: `assets/levels/extra/*.map`;
- классические карты: `assets/levels/classic/*.map`;
- неиспользуемая карта из `$A800`: `assets/levels/unused/001.map`;
- тайлы спрайтов: `assets/chr/sprites.bmp`;
- фоновые тайлы: `assets/chr/background.bmp`;
- палитры: `assets/palettes/*.pal`;
- фоновые метатайлы 2×2: `assets/metatiles/background.tsa`;
- игровой код и таблицы: `src/*.s` и `src/*.inc`.

Основные таблицы диспетчеризации используют символические ссылки:
`TankLogicHandlers` и `TankDrawHandlers` находятся в `src/tank_tables.s`,
`ProjectileLogicHandlers` и `ProjectileDrawHandlers` — в `src/projectiles.s`,
`PowerUpEffectHandlers` — в `src/powerup_pickup.s`, а `AudioCommandHandlers` —
в `src/audio.s`. Логика состояний танков находится в `src/tanks.s`.
Адреса устойчивых игровых полей собраны в `src/ram.inc`, а общие коды состояний,
маски и размеры пулов — в `src/game.inc`. Один и тот же байт RAM иногда
переиспользуется разными экранами; такие рабочие значения намеренно именуются
локально в соответствующем модуле.
У аудиопотоков есть точки входа `AudioSequence00`–`AudioSequence27`; несколько
потоков могут совместно использовать один и тот же хвост данных. Значения
`AudioStreamStates` равны 0 для выключенного потока, 1 для запроса запуска и 2
для работающего потока; подтверждённые игровые звуки имеют отдельные алиасы в
`ram.inc`. Формат
потоков и команды интерпретатора описаны в `docs/audio.md`.

BMP используют только индексы палитры 0–3. Цвета BMP нужны для удобного
просмотра; в NES окончательный цвет задаётся палитрами из PRG.

## Ограничения текущей раскладки

Конфигурация `cfg/tank1990.cfg` фиксирует адреса областей оригинального NROM.
Изменение байтов внутри области допустимо, но её переполнение остановит
линковку. Это специально защищает таблицы уровней, векторы и код от незаметного
сдвига. Для расширения ROM нужно завести отдельную конфигурацию линкера и
изменить iNES-заголовок/mapper осознанно.

Метки `Lxxxx` сохраняют исходные CPU-адреса и удобны при сверке с отладчиком,
но не считаются стабильным API. Смысловые имена из `ram.inc`, имена процедур и
имена таблиц без адресного префикса предпочтительны для нового кода.

Часть физических диапазонов разбита на смысловые файлы, подключаемые через
`.include` из исходного места. Для производной работы следует открывать файл
подсистемы из таблицы `docs/memory-map.md`; файл-контейнер нужен прежде всего для
сохранения порядка. Переносить сам `.include` без одновременного изменения
линкерной раскладки нельзя: абсолютные адреса, таблицы обработчиков и переходы
между continuation-метками рассчитывают на исходное расположение.
