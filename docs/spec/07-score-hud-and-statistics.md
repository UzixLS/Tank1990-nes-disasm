# Счёт, жизни, HUD и статистика

## Представление счёта

Каждый счёт и рекорд хранятся как семь отдельных десятичных цифр. Диапазон:

```text
0 .. 9 999 999
```

Сложение идёт справа налево с десятичным переносом. Переполнение старшей цифры отбрасывается, то есть счёт работает по модулю 10 000 000.

Холодный старт устанавливает рекорд 20 000. Постоянного сохранения нет.

## Награды

| Событие | Очки |
|---|---:|
| противник типа `0x80` | 100 |
| противник типа `0xA0` | 200 |
| противник типа `0xC0` | 300 |
| противник типа `0xE0` | 400 |
| бонус, взятый игроком | 500 |
| победитель этапа в 2P | 1 000 |

Очки за противника получает владелец попавшего снаряда: чётный логический слот — P1, нечётный — P2. Attract mode подавляет награду и проверку дополнительной жизни, но всё равно увеличивает счётчик убитого типа.

Grenade не начисляет очков и не увеличивает статистику.

## Дополнительная жизнь за очки

Каждый игрок может получить такую жизнь не более одного раза за сессию. После прибавления очков код проверяет цифру десятков тысяч. Если она не меньше 2 и бой активен, игроку добавляется жизнь и устанавливается флаг уже выданной награды.

При обычном монотонном счёте это порог 20 000. Из-за десятичного переполнения и прямой проверки цифры возможны экзотические состояния, но повторной награды флаг не допускает.

Проверка идёт сначала для P1, затем для P2. Если P1 получает жизнь, процедура сразу заканчивается, поэтому одновременно готовый P2 дождётся следующего начисления/проверки. У каждого свой флаг; P2 проверяется только в двухпользовательском режиме.

## Жизни и возрождение

Число жизней — беззнаковый байт. Бонус Tank и порог очков увеличивают его по модулю 256.

При инициализации этапа игрок с ненулевым счётчиком появляется без расхода жизни. Когда завершается 24-шаговая анимация его уничтожения, система:

1. уменьшает число жизней;
2. если результат ненулевой, создаёт танк в нижней точке;
3. запускает 28 обслуживаний анимации появления;
4. при завершении делает танк активным вверх;
5. при нуле оставляет слот пустым и считает игрока выбывшим.

Точка появления игрока не проверяется на занятость: новый объект создаётся сразу и очищает свой метатайл 16×16. Если оба игрока пусты и жизней нет, этап проигран.

### Передача жизни в 2P

Во время боя выбывший игрок может удерживать `A`, чтобы забрать одну жизнь у партнёра и немедленно появиться. Донор должен иметь не меньше двух жизней, поэтому после передачи у него остаётся хотя бы одна.

Проверка асимметрична [ROM]:

1. пока `P2 lives != 0`, проверяется только мёртвый P1; `P1 A` переносит жизнь от P2 к P1;
2. только когда `P2 lives == 0`, `P2 A` может перенести жизнь от P1 к P2.

Используется удержание, а не фронт кнопки. Появление выполняется сразу, без проверки занятой клетки. Это отдельная механика от послебоевого секретного chord, который восстанавливает три жизни.

## Правый HUD

Во время боя справа отображаются:

- ещё не выпущенные противники в виде до 20 маленьких значков;
- число жизней P1;
- число жизней P2 в двухпользовательском режиме;
- номер этапа;
- символы принадлежности игроков и базы.

Счёт во время самого боя не показан; он виден на переходных и статистических экранах. Число жизней обновляется каждый игровой такт, но во время паузы остаётся последним подготовленным значением.

Значки противников отражают ещё **не выпущенные** на поле единицы. Один значок очищается в момент начала каждого spawn. Отдельный невидимый `enemiesRemaining` уменьшается после конца анимации уничтожения; именно он определяет победу.

### Точная разметка HUD

Координаты указаны в тайлах 8×8:

| Элемент | Столбец | Строка/диапазон |
|---|---:|---:|
| сетка 20 противников, 2×10 | 29..30 | 3..12 |
| метка P1 | 29 | 17 |
| значок жизни P1 | 29 | 18 |
| число запаса P1 | 25 | 18 |
| метка P2 | 29 | 20 |
| значок жизни P2 | 29 | 21 |
| число запаса P2 | 25 | 21 |
| двухстрочный значок Stage | 29 | 23..24 |
| номер этапа | 25 | 25 |

Число запаса равно `max(lives - 1, 0)`. Для байтов `0x81..0xFF` оригинальная знаковая проверка также выводит ноль; это имеет значение только для искусственно переполненных жизней.

## Счётчики этапа

Для каждого игрока хранятся четыре байтовых числа уничтоженных типов. При обычном убийстве индекс типа вычисляется из высокого класса атрибута. На экране статистики для каждой строки показываются:

```text
count × [100, 200, 300, 400] = award
```

Показанная сумма — уже начисленные во время боя очки. Экран статистики НЕ добавляет её второй раз.

Общий счётчик убийств этапа складывается как байт по модулю 256. В штатном этапе максимум 20, поэтому переполнение невозможно без модификации игры.

## Анимация статистики

Нормативные задержки в кадрах:

| Фаза | Длительность |
|---|---:|
| вводный экран | 30 |
| перед итогами | 30 |
| один шаг счётчика строки | 8 |
| между строками | 20 |
| показ победителя/бонуса | 15 |
| финальная пауза | 120 |

Четыре типа появляются последовательно. Для каждого счётчик визуально увеличивается по одному, синхронно меняя показанные очки строки и итог уничтожений.

## Бонус победителя в 2P

После подсчёта в режиме двух игроков при ненулевом `battleState` 1 000 очков получает игрок, который:

- имеет строго больше уничтоженных противников на этом этапе;
- имеет ненулевое число жизней;
- сравнивается на экране статистики до возврата к титулу или следующему этапу.

При равенстве бонуса нет. Если лидер выбыл окончательно, второй игрок не получает бонус автоматически. После прибавления 1 000 выполняется обычная проверка порога дополнительной жизни.

### Точная разметка статистики

Заголовок рекорда стоит в строке 3, номер этапа — в строке 5, заголовки игроков — в строке 7, их счета — в строке 9. Четыре типа противников занимают строки 12, 15, 18 и 21; `TOTAL` — строку 23, бонус победителя — строки 25–26. P1 занимает левую половину, P2 правую. Значки типов привязаны к экранному X=`0x81`, Y=`0x64,0x7C,0x94,0xAC`.

## Рекорд

После подходящего результата сравнение выполняется строго: новый счёт должен быть больше текущего рекорда. Равенство не заменяет рекорд.

Порядок кандидатов:

1. P1;
2. P2.

Поэтому если оба в одной сессии последовательно превосходят старое значение, итогом становится больший из них; при точном равенстве первым остаётся P1.

## Отображение чисел

В большинстве экранов ведущие нули скрываются, но полностью нулевое поле показывает один `0`. Номер этапа переводится как беззнаковый байт 0..255. Экран статистики показывает не более шести младших разрядов счёта, хотя внутренняя запись содержит семь.
