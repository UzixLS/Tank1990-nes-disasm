# Нормативные данные и форматы

## Состав переносимого пакета

Чтобы воссоздать поведение без ROM и дизассемблированного исходника, вместе с главами спецификации передаются следующие данные:

```text
docs/spec/audio-bytecode.hex
assets/chr/background.bmp
assets/chr/sprites.bmp
assets/palettes/background.pal
assets/palettes/sprites.pal
assets/metatiles/background.tsa
assets/levels/classic/001.map .. 036.map
```

Это и есть **нормативный пакет спецификации**. Файл [assets.sha256](assets.sha256) проверяет текстовые/графические представления. Ни исходный `.nes`, ни 6502-код для реализации не требуются.

Если цель — самостоятельная игра с новой графикой и музыкой, CHR, палитры и audio bytecode МОЖНО заменить. Карты, тайминги, размеры и поведение при этом остаются нормативными.

## CHR BMP

Требования к каждому файлу:

- размер 128×128;
- несжатый 8-bit indexed BMP;
- только индексы пикселей 0, 1, 2, 3;
- 16 плиток по горизонтали и 16 по вертикали;
- порядок плиток row-major;
- внутри плитки порядок пикселей сверху вниз, слева направо.

Кодирование одной плитки в NES planar format:

```text
for y in 0..7:
    plane0[y] = sum(((pixel[x,y] >> 0) & 1) << (7-x))
for y in 0..7:
    plane1[y] = sum(((pixel[x,y] >> 1) & 1) << (7-x))
```

Сначала идут восемь байтов plane 0, затем восемь plane 1. Полная таблица — 256×16 = 4096 байт.

## Палитры

Текстовый формат допускает пустые строки, комментарии после `#` и hex-токены `00..3F`.

- `sprites.pal` обязан дать 16 байт;
- `background.pal` — 9 последовательных наборов по 16, всего 144.

В каждом 16-байтовом наборе четыре группы по четыре цвета. Нулевой цвет каждой группы прозрачен/универсален по правилам NES PPU.

## Метатайлы

Каждая непустая строка `background.tsa`:

```text
palette  topLeft  topRight  bottomLeft  bottomRight
```

`palette` находится в 0..3, номера плиток — в 0..255. Ровно 16 строк кодируются как:

```text
16 байт номеров палитр
64 байта плиток, по TL/TR/BL/BR для каждой строки
```

Индекс строки является значением метатайла в карте.

## Карты

Текстовая карта имеет 13 строк. Каждая содержит 14 hex-полубайт:

```text
a0 a1 ... a12 | padding
```

Первые 13 — видимые метатайлы. Значение после `|` не рисуется, но сохраняется, потому что влияет на байтовый поток и сдвинутые варианты уровней.

Кодирование строки:

```text
byte0 = a0 << 4 | a1
byte1 = a2 << 4 | a3
...
byte5 = a10 << 4 | a11
byte6 = a12 << 4 | padding
```

Одна карта — 13×7 = 91 байт. Каталог — конкатенация `001`…`036` без заголовка. Сразу после него для сдвинутого крайнего окна считаются доступными четыре нормативных хвостовых байта:

```text
20 D2 0D 2D
```

Они не являются 37-й картой. Это реальные следующие байты ROM, случайно захватываемые загрузчиком при фазе +2/+4.

## Аудиоданные

Файл [audio-bytecode.hex](audio-bytecode.hex) содержит адресованные байты:

| Диапазон | Назначение |
|---|---|
| `ECE6..ECFD` | 12 пар base periods, high затем low |
| `ECFE..ED35` | 28 little-endian CPU pointers |
| `ED36..EF75` | разделяемые последовательности bytecode |

Индекс потока задаёт приоритет и назначение:

| № | Назначение |
|---:|---|
| 0 | Pause |
| 1 | Stage intro, pulse 1 |
| 2 | Stage intro, triangle |
| 3 | Stage intro, pulse 2 |
| 4 | Extra life, pulse 1 |
| 5 | Extra life, pulse 2 |
| 6 | Power-up pickup |
| 7 | Player/base destruction noise |
| 8 | неидентифицированный штатный поток |
| 9 | Power-up spawn |
| 10 | Tank destruction |
| 11 | Base destruction tone |
| 12 | Brick hit |
| 13 | Ricochet/menu step |
| 14 | Armor hit |
| 15 | Player fire |
| 16 | Ice slide start |
| 17 | Player movement loop |
| 18 | Gameplay loop |
| 19 | Statistics count pulse |
| 20 | Statistics count noise |
| 21 | New high score pulse 1 |
| 22 | New high score pulse 2 |
| 23 | New high score triangle |
| 24..26 | неидентифицированные штатные потоки |
| 27 | Statistics winner bonus |

Адреса в pointer table относятся к CPU-диапазону файла. Для переноса:

```text
sequenceOffset = pointer - 0xECE6
```

Последовательности имеют общие хвосты; нельзя определять длину просто вычитанием соседних указателей. Интерпретатор следует выполнять до `E8` либо бесконечного `F9`-цикла.

## Данные, не входящие в штатную игру

Следующие файлы сохранены как исследовательский материал и не нужны для совместимой реализации:

- `assets/levels/extra/001.map`…`105.map`;
- `assets/levels/unused/001.map`.

Их включение в пользовательское расширение допустимо, но это новый контент, а не восстановление выбора уровней данного ROM.
