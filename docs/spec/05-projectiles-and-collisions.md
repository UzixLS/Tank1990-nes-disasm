# Снаряды и столкновения

## Слоты снарядов

Имеется десять слотов:

| Слот | Владелец |
|---:|---|
| 0 | основной снаряд P1 |
| 1 | основной снаряд P2 |
| 2..7 | по одному для соответствующего противника |
| 8 | дополнительный снаряд P1 |
| 9 | дополнительный снаряд P2 |

Логический владелец игрока вычисляется как `slot & 1`; пары одного владельца — 0/8 и 1/9.

## Состояния и жизненный цикл

Активный снаряд имеет состояние:

```text
0x40 | direction
```

Он создаётся на восемь пикселей впереди центра танка. Существующий активный снаряд сначала двигается, затем проходит проверки столкновений. Созданный в текущем такте снаряд пропускает движение, но участвует в столкновениях того же такта.

После попадания состояние становится `0x33`. Анимация проходит:

```text
0x33 -> 0x32 -> 0x31 ->
0x23 -> 0x22 -> 0x21 ->
0x13 -> 0x12 -> 0x11 -> 0x00
```

То есть видимый impact существует девять логических тактов: три графические фазы по три такта.

## Скорость и флаги

Медленный снаряд сдвигается на 2 пикселя за такт, быстрый — на 4. Флаг `breakSteel` позволяет разрушить целый байт стали.

В стандартных вариантах A–G флаги по высокому классу атрибута танка декодируются так:

| Класс атрибута | Скорость | Сталь |
|---|---|---|
| `0x00` | 2 | нет |
| `0x10..0x50` | 4 | нет |
| `0x60` | 4 | да |
| `0x70` | 4 | нет |
| `0x80,0x90` | 2 | нет |
| `0xA0..0xB0` | 2 | нет |
| `0xC0` | 4 | нет |
| `0xD0..0xF0` | 2 | нет |

В расширенных вариантах H–N:

- установленный bit 3 атрибута даёт быстрый снаряд с `breakSteel`;
- класс `0x60` даёт `breakSteel`;
- классы `0x10..0x50`, `0x70`, `0xA0..0xF0` быстрые;
- классы `0x00`, `0x80`, `0x90` медленные.

Эта таблица применяется к сырым атрибутам и иногда даёт намеренно странный результат после бонусов противника.

## Огонь игроков

В обычном режиме попытка выстрела происходит при:

- новом нажатии `A`; или
- удерживаемом `B`.

В режиме объединённого огня используются новые нажатия `A` или `B`.

Если основной слот уже занят, новый выстрел обычно запрещён. При уровне, разрешающем два снаряда, выполняется особый перенос:

1. если основной слот занят, а дополнительный свободен, состояние, позиция и флаги основного копируются в дополнительный;
2. основной очищается;
3. новый снаряд создаётся в основном слоте.

Условие двойного выстрела — `(objectAttributes & 0xC0) == 0x40`.

## Порядок разрешения столкновений

За один такт категории обрабатываются строго так:

1. снаряд → местность/база;
2. снаряд ↔ снаряд;
3. снаряд → танк.

Если более ранняя фаза перевела снаряд из класса `0x40` в impact, следующие фазы его пропускают. Поэтому снаряд, встретивший кирпич в том же кадре, уже не поражает стоящий за ним танк.

## Столкновение с местностью

Слоты проверяются в обратном порядке 9..0. Снаряд с нулевыми флагами проверяется только на кадрах, где:

```text
(slot XOR frameCounter) & 1 == 1
```

Снаряд с любым флагом проверяется каждый кадр. Это снижает точность медленных обычных пуль и является заметной частью оригинальной физики.

### Пробные точки

Знак направления не влияет на набор точек, только ось. Для вертикального полёта последовательно пробуются:

```text
(x,   y)
(x+4, y)  только если первая точка сняла частичный 4×4-бит
(x-1, y)
(x-5, y)  только если третья точка сняла частичный 4×4-бит
```

Для горизонтального:

```text
(x, y)
(x, y+4)  только после частичного разрушения первой
(x, y-1)
(x, y-5)  только после частичного разрушения третьей
```

Координаты 8-битные. Даже если первая половина перевела снаряд в impact, вторая ближняя точка текущего прохода всё равно проверяется. Так один снаряд иногда повреждает две соседние 4×4-части.

Результат по типам местности определён в [главе о поле](03-playfield-levels-and-terrain.md).

## Столкновение снаряд-снаряд

Проверяются только логические снаряды игроков против всех снарядов другого владельца:

- пары одного игрока 0/8 и 1/9 между собой не сталкиваются;
- снаряды противников друг с другом не сталкиваются;
- один и тот же логический снаряд не сравнивается с самим собой.

Два активных снаряда сталкиваются, если по каждой оси выполняется:

```text
absWrapped(a - b) < 6
```

Оба сразу очищаются в состояние 0, без impact-анимации.

## Столкновение с танком

Условие попадания:

```text
absWrapped(projectile.x - tank.x) < 10
AND
absWrapped(projectile.y - tank.y) < 10
```

`absWrapped` сначала выполняет 8-битное вычитание, затем берёт модуль знакового результата.

Вражеские снаряды 2..7 проверяются только против P1/P2. Игровые снаряды 0,1,8,9 проверяются только против противников. Дружественного огня между игроками в этом ROM нет. Официальная механика оглушения союзника из Battle City здесь не применяется [ROM].

**[точная совместимость]** Танковые коллизии обходят игроков, затем два полных раза противников 7..2. Обычно второй проход ничего не меняет, потому что попавший снаряд уже стал impact, но структуру следует сохранять в дифференциальной реализации.

### Попадание в игрока

Эффекты имеют следующий приоритет:

1. активный щит удаляет снаряд без impact-анимации и не меняет игрока;
2. Boat поглощает попадание, очищает специальное состояние и оставляет снаряд в impact;
3. максимальный обычный апгрейд 63 понижается до 40 и включает звук брони;
4. иначе танк переходит в уничтожение `0x73`, специальное состояние очищается, а обычное улучшение, расширенное улучшение и атрибут танка синхронно сбрасываются в 0 для A–G или 20 для H–N.

Щит проверяется раньше Boat и поэтому не расходует Boat.

### Попадание в противника

1. снаряд игрока становится impact;
2. если установлен бит носителя, создаётся новый бонус;
3. если младшие два бита HP ненулевые, атрибут уменьшается на 1 и проигрывается звук брони;
4. иначе танк переходит в уничтожение, обновляет статистику владельца снаряда и получает награду 100/200/300/400.

Тип для статистики вычисляется буквально:

```text
typeIndex = (attributes >> 5) - 4
```

Нормальные классы `0x80,0xA0,0xC0,0xE0` дают индексы 0..3. Код не ограничивает результат; необычные атрибуты после бонусов могут обратиться к соседним данным. Для безопасной современной копии разрешено ограничить индекс 0..3, но режим точной совместимости должен сохранить сырое вычисление.

## Столкновение с базой

База проверяется как часть фазы местности, до танков. Попадание в любой из четырёх кодов целой базы `0xC8..0xCB` при активном бое запускает уничтожение. При уже нулевом `battleState` эти коды проходят через общий классификатор и не обязаны вновь менять состояние боя.

## Звуковые асимметрии слотов

Физика дополнительных снарядов 8/9 считает их выстрелами игроков. Некоторые звуковые ветви, однако, проверяют только `slot < 2`:

- разрушение кирпича и рикошет звучат для основных 0/1;
- те же события дополнительного 8/9 могут пройти без соответствующего звука.

Эта деталь нужна только для точного звукового совпадения.
