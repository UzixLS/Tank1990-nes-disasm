# Tank 1990 (Ch) — исходный код

Проект восстанавливает исходный код и ассеты NES-игры `Tank 1990 (Ch).nes`.
Результат собирается ca65/ld65 и побайтово совпадает с исходным образом.

## Сборка

Требуются GNU Make, cc65 2.19 и Python 3.12. Сторонние Python-пакеты не
используются. Локальные пути к инструментам можно переопределить в
игнорируемом `Makefile.local`; заготовка — `Makefile.local.example`.

```sh
make all
make verify
make test
```

Собранный образ находится в `build/tank1990-ch.nes`. Цель `verify` сравнивает
его с оригиналом и проверяет SHA-256
`ec453e7e3cc1d49d11d5860ced7f9e1235e2c7d33927bd6073b631754dc08dbb`.
Обычная сборка не читает исходный NES-файл.

`make audit` дополнительно извлекает заголовок, PRG- и CHR-банки оригинала в
`build/original/`. Эти временные файлы не являются исходниками и не хранятся
в репозитории.

## Редактирование ассетов

- `assets/chr/sprites.bmp` и `background.bmp` — две NES pattern table по 256
  тайлов. Это несжатые 8-bit indexed BMP 128×128; допустимы индексы 0–3.
- `assets/palettes/*.pal` — палитра спрайтов и девять наборов фоновой палитры;
  значения записаны как шестнадцатеричные индексы цветов NES `00`–`3F`.
- `assets/metatiles/background.tsa` — 16 блоков 2×2: номер подпалитры и четыре
  индекса фоновых CHR-тайлов. Номер строки совпадает со значением в карте.
- `assets/levels/tank/*.map` — 100 карт Tank 1990.
- `assets/levels/extra/*.map` — ещё 5 записей того же формата из `$A38C`;
  их игровое назначение пока обозначено нейтрально.
- `assets/levels/classic/*.map` — 36 встроенных классических карт.
- `assets/levels/unused/001.map` — неиспользуемая карта из `$A800`, сохранённая
  в ROM без обнаруженной ссылки; вынесена отдельно для редактирования и анализа.

Карта состоит из 13 строк. В каждой строке первые 13 hex-значений задают
TSA-блоки игрового поля, а значение после `|` сохраняет неиспользуемый
ниббл-заполнитель оригинального формата. Конвертеры проверяют размеры и выполняют
обратное кодирование без потерь.

## Организация ASM

`src/header.s` содержит iNES-заголовок, `src/levels.s` подключает карты, а
`src/chr.s` — собранную графику. Исполняемый код разделён по игровым подсистемам:
цикл игры и экраны, PPU и OAM, ввод, счёт, танки, снаряды, усиления,
столкновения, звук и загрузка этапов. Небольшие смысловые модули подключаются
из файлов-владельцев через `.include` ровно в позиции оригинального ROM: это
сохраняет адреса и одновременно позволяет менять подсистему для ромхака без
поиска её частей в несвязанных крупных файлах. Точная карта приведена в
`docs/memory-map.md`.
Физические адреса областей ROM фиксирует `cfg/tank1990.cfg`.
Подтверждённая карта рабочей памяти и состояний аудиопотоков находится в
`src/ram.inc`, общие размеры пулов, маски и коды состояний — в `src/game.inc`.
Перегруженные временные байты получают локальные имена возле использующих их
процедур и не выдаются за глобальные игровые переменные.

Имена вида `Lxxxx` сохранены как адресные якоря оригинального ROM и не являются
публичным интерфейсом. Для нового кода следует использовать расположенные рядом
смысловые имена процедур, таблиц и переменных. Порядок и размер данных необходимо
сохранять, пока требуется побайтовая совместимость.

Практические замечания по созданию производных версий находятся в
`docs/hacking.md`, описание музыкального интерпретатора — в `docs/audio.md`.

`BC_SourceCode.asm` допускается использовать только как справочник при
проверке спорной интерпретации. Имена и комментарии из него в этот проект не
переносятся.
